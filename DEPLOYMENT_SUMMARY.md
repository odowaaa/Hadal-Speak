- **Advanced manifest capabilities:** see "Manifest capabilities" section below

## What you still need to do

1. **Package it as an Android app** with PWABuilder or Bubblewrap (Step 3) —
   point it at `https://hadal-speak.vercel.app/`.
2. **Add `.well-known/assetlinks.json`** with your app's signing fingerprint so
   the installed app opens without a browser address bar (Step 4).
3. **Create a 1024x500 feature graphic** for the Play Store listing (separate
   from the in-app screenshots — a promotional banner image; not yet in this
   repo).
4. **Submit to Google Play Console** (Step 5) — the Data Safety form should
   declare "no data collected or shared," since there is no server.
5. **Once the Play Store listing is live:** flip `prefer_related_applications`
   to `true` in `manifest.json` and confirm `related_applications[0].id`
   matches the package name you actually published under (see "Manifest
   capabilities" below).

## Manifest capabilities

Added, with real behavior behind them (not just declared):

- **`display_override`** — tries `standalone` first, falling back gracefully.
- **`launch_handler: focus-existing`** — reopening the installed app focuses
  the existing window instead of spawning a duplicate.
- **`edge_side_panel`** — sets a 448px preferred width (matches the app's
  mobile-first `max-w-md` layout) for Microsoft Edge's side panel.
- **`protocol_handlers`** — registers `web+hadalenglish://lesson/<lessonId>`;
  a new `/protocol-handler` route (`client/src/pages/protocol-handler.tsx`)
  resolves it to the matching lesson and redirects there.
- **`share_target`** — the OS "Share to…" menu can send text to
  `/practice?shared_text=…`; the Practice page shows it in a dismissible card
  with audio playback and voice-recording practice, so a sentence copied from
  anywhere can be practiced immediately.
- **`related_applications` / `prefer_related_applications`** — added a
  `play` entry pointing at the suggested package id, but
  `prefer_related_applications` is deliberately `false` until that Play Store
  listing actually exists; flipping it early would suppress the PWA install
  prompt in favor of a native app that isn't published yet.

Deliberately **not** added (would be a fabricated capability with no real
behavior behind it, and no way to add real behavior without functionality
the app doesn't have):

- **`file_handlers`** — for apps that open specific file types from the OS
  (e.g. a document editor). Hadal English doesn't consume any files.
- **`note_taking`** — a hook for OS "new note" shortcuts, meant for
  note-taking apps (OneNote, Keep, etc.). Not applicable here.
- **`widgets`** — Windows 11 Widgets Board support requires an Adaptive Card
  template plus service-worker `widgetinstall`/`widgetresume` handling, aimed
  at desktop Windows users; this app's audience is mobile/Android via TWA, so
  the effort wouldn't serve real users.
- **`scope_extensions`** — extends the app's scope to other origins you also
  control (validated via `.well-known/web-app-origin-association` on each
  one). There's only one origin here.
- **`iarc_rating_id`** — this is generated by completing a content-rating
  questionnaire (Google Play Console has its own version of this in Step 5
  of `GOOGLE_PLAY_DEPLOYMENT_GUIDE.md`; the manifest field itself is mainly
  read by Microsoft Store, not Google Play). It has to come from that real
  questionnaire — a placeholder ID would just be wrong data, so it's left out
  of the manifest until you have a real one.
